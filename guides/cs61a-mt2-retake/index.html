How to use this

Four sections are marked focus: mutation and aliasing, higher-order functions, sequences and comprehensions, and tree navigation. Those are where points actually leak, so read them slowly and do the practice problems in each. The remaining sections (recursion, environment diagrams, linked lists) are refreshers for things you already handle well, there to keep them sharp.

The habit that matters most on a paper exam: trace by hand, one tiny step at a time. Most lost points on MT2 are not from not knowing the idea; they are from doing two steps in your head at once and skipping the one that mattered.

Focus area

Mutation & aliasing

This is the single biggest source of lost points on MT2. The whole topic is one question: are these two names the same list object, or two different lists?

The one rule

= never copies a list. It just gives the same object another name. To get a new list you must slice it, call list(), or build one with a comprehension.

a = [1, 2, 3]
b = a          # SAME list. a and b are two names for it.
c = a[:]       # NEW list (a copy). c is independent.
d = list(a)    # NEW list (a copy).
e = [x for x in a]   # NEW list (a copy).

So mutating through one name is seen by every alias, but never by a copy:

a = [1, 2, 3]
b = a
c = a[:]
b.append(4)    # changes the one shared list
# a is [1, 2, 3, 4]   (b is the same object)
# c is [1, 2, 3]      (c was a copy, untouched)

The trap you hit: treating a[:] like b = a. They are opposites. b = a aliases; a[:] copies. If a question slices a list, a new list is born on that line.

Because mutating methods return None: never write a = a.append(4). That sets a to None. Just write a.append(4) on its own line.

How to answer a box-and-pointer question

Draw one box per list object, not one per name. An arrow is a name pointing at an object. When a line says b = a, draw a second arrow to the same box. When a line slices or builds, draw a new box. Then apply each mutation to the box its name points at.

s = [1, 2, 3]
t = s[1:]      # NEW box [2, 3]
t.append(4)    # t's box becomes [2, 3, 4]
s[0] = t       # s's first slot now points at t's box
# s displays [[2, 3, 4], 2, 3] ; t displays [2, 3, 4]

The reason s shows [2, 3, 4] inside it is that s[0] and t point at the same box, so printing s shows whatever that box currently holds.

Focus area

Higher-order functions & lambdas

A higher-order function is just a function that either takes a function as an argument or returns a function. You already know it returns a function; the gap is tracing what happens when you then apply it.

A function value vs. calling it

def make_adder(n):
    def adder(k):
        return k + n
    return adder

make_adder(3)        # a FUNCTION (adder, which remembers n = 3)
make_adder(3)(4)     # 7  (now we call that function with k = 4)

make_adder(3) hands back a function. The second pair of parentheses is a separate call on that returned function. Two sets of parentheses means two calls, left to right.

Applying a function twice: evaluate inside-out

f(f(x)) means: first compute f(x), then feed that result back into f. Innermost parentheses first, always.

square = lambda x: x * x
(lambda f, x: f(f(x)))(square, 2)
# step 1: f(2) = square(2) = 4
# step 2: f(4) = square(4) = 16
# result: 16   (NOT 8)

The trap you hit: collapsing f(f(2)) into one operation. Do it in two steps on paper: write down f(2)'s value, then apply f to that. Same for g(g(3)) with g = lambda n: n + 1: g(3) = 4, then g(4) = 5.

Lambdas are just functions

lambda x: x * x is the same as def _(x): return x * x, but as an expression with no name. It can be passed around, returned, and called like any function. A lambda has exactly one expression as its body, no statements.

compose = lambda f, g: lambda x: f(g(x))   # returns a new function
h = compose(lambda x: x + 1, lambda x: x * 2)
h(5)   # f(g(5)) = (5*2) + 1 = 11

Read a returned lambda the same way as a returned def: it remembers the variables from where it was created (here f and g).

Focus area

Sequences & comprehensions

Slicing

s[start:stop] includes start, excludes stop, and always returns a new list. Omit an end to go to the edge; a negative index counts from the right.

s = [10, 20, 30, 40, 50]
s[1:3]    # [20, 30]      (index 1 and 2, not 3)
s[:2]     # [10, 20]
s[2:]     # [30, 40, 50]
s[-1]     # 50            (last element)
s[::-1]   # [50, 40, 30, 20, 10]  (reversed copy)

Comprehensions: filter first, then transform

Read [EXPR for x in SEQ if COND] as two steps: keep each x where COND is true, then compute EXPR on the survivors.

[x * 2 for x in [1, 2, 3, 4] if x % 2 == 0]
# step 1 (filter): keep evens -> 2, 4
# step 2 (transform): x * 2 -> 4, 8
# result: [4, 8]

The trap you hit: misreading the expression. x * 2 doubles (4, 8); x ** 2 or x * x squares (4, 16). The exam puts these near each other on purpose. Read the operator, then the filter, out loud if you have to.

Focus area

Trees (the ADT)

A Tree has a label and a list of branches, each of which is itself a Tree. A leaf is a tree with no branches: is_leaf(t) is not t.branches.

t = Tree(1, [Tree(2), Tree(3, [Tree(4)])])
t.label          # 1
t.branches       # [Tree(2), Tree(3, [Tree(4)])]
t.branches[0]    # Tree(2)        (the FIRST branch)
t.branches[1]    # Tree(3, [Tree(4)])   (the SECOND branch)

Navigating: indexing is 0-based

branches[0] is the first branch, branches[1] is the second. Walk a chain one attribute at a time and write down what each step evaluates to.

t.branches[1].branches[0].label
# t.branches[1]            -> Tree(3, [Tree(4)])
# .branches[0]            -> Tree(4)
# .label                  -> 4

The trap you hit: reading branches[1] as the first branch. Index 0 is first, 1 is second. On a chain like this, never evaluate two links in your head at once; write the intermediate tree down, then take the next step.

Recursion on trees

Almost every tree function loops over t.branches and recurses on each branch, combining the results with the current label.

def tree_sum(t):
    return t.label + sum(tree_sum(b) for b in t.branches)

def count_leaves(t):
    if is_leaf(t):
        return 1
    return sum(count_leaves(b) for b in t.branches)

def height(t):
    if is_leaf(t):
        return 0
    return 1 + max(height(b) for b in t.branches)

To build a new tree, wrap the recursive results in a fresh Tree, never mutate the input: Tree(t.label * 2, [double(b) for b in t.branches]).

Recursion & tree recursion

You have this down, so this is a refresher plus the harder patterns to expect on a retake.

The three-step contract

  1. Base case: the smallest input, answered directly, returning the right type.
  2. Recursive call: on a strictly smaller input, which you trust to be correct.
  3. Combine: use that result with the current piece to build the answer.

Tree recursion (two or more calls)

When each step branches into several calls, you are enumerating choices. The with/without pattern covers most of it:

def count_ways(s, n):
    if n == 0:
        return 1          # one valid way: used up the target exactly
    if n < 0 or not s:
        return 0          # overshot, or ran out of items
    use  = count_ways(s[1:], n - s[0])   # take s[0]
    skip = count_ways(s[1:], n)          # leave s[0]
    return use + skip

Swap the combine step for the question: use + skip to count, use or skip for yes/no, max(use, skip) for best. Put the n < 0 and empty checks before any s[0].

Harder retake twist: expect a second parameter you carry down (a remaining budget, a running total, or a "minimum allowed" value). Decide what to carry before you write the body, then the base case and the recursive calls follow.

Environment diagrams

You handled scope correctly on the diagnostic, so just hold the one rule that decides every hard case: a function looks up names in the frame where it was defined, not where it is called.

x = 1
def f():
    x = 2
    def g():
        return x     # no local x -> look in g's PARENT (f's frame) -> 2
    return g()
f()   # 2

Each call makes a new frame. A name not found locally is looked up in the parent frame (the frame where the function was defined), then the global frame. When you draw a function value, note its parent; that is the chain its body will search.

Linked lists

A Link has first (its value) and rest (the rest of the list, another Link or Link.empty). Recurse on s.rest, build new Links going back up.

def link_sum(s):
    if s is Link.empty:
        return 0
    return s.first + link_sum(s.rest)

def keep_even(s):
    if s is Link.empty:
        return s
    rest = keep_even(s.rest)
    if s.first % 2 == 0:
        return Link(s.first, rest)   # new node in front
    return rest                      # drop s.first

The base case is s is Link.empty, not s.rest is Link.empty. Access a chain one step at a time: s.rest.rest.first is the third value.

Exam-day checklist

Tuned to the things that cost you points on the diagnostic.

  1. On any list line, ask "new list or same list?" = shares; slicing, list(), and comprehensions copy.
  2. A mutating method returns None. Never a = a.append(x).
  3. Evaluate nested calls inside-out. f(f(x)) is two steps; write the inner value down first.
  4. Two sets of parentheses means two calls. make(3)(4) calls the returned function.
  5. Read the comprehension operator exactly. * 2 doubles, ** 2 squares. Filter first, then transform.
  6. Indexing is 0-based. branches[1] is the second branch. Walk chains one attribute at a time.
  7. Recursion: base case returns the right type, every call shrinks the input, and you carry down whatever state the problem needs.
  8. Trace by hand, one small step at a time. Most of your lost points are skipped steps, not missing knowledge.

Then put it to work in the practice app: redo the mutation, higher-order, and tree problems cold until the traps above feel automatic.
