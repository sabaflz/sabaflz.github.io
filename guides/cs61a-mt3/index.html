Scope & format

Midterm 3 is Tuesday 10/27, 8:00–10:00pm, 110 minutes, on paper. Materials start at 8:00, the exam starts 8:10. You get a seat assignment by email Monday night; email cs61a@berkeley.edu if it hasn't arrived by Tuesday morning. The three study guides (MT1, MT2, MT3) and scratch paper are provided.

Because it's on paper there's no autograder to lean on: your code has to be right by reading, and partial credit is on the table, so write the structure even when you're unsure of a detail.

You may bring: pencils (plus a spare), photo ID, two 8.5×11 sheets of notes (front and back) you make yourself, a drink, non-digital ear plugs. Everything else is closed.

In scope (through Lecture 24, Efficiency)

  • Recursion and tree recursion
  • Sequences: lists, slicing, comprehensions, for, ranges, aggregation
  • Dictionaries
  • Higher-order functions and lambdas
  • Linked lists (non-mutating)
  • Trees (the Tree label/branches abstraction)
  • List and dictionary mutation (append, pop, item assignment, +=, aliasing, is vs ==)
  • Box-and-pointer / environment diagrams, including closures that hold state
  • Iterators (iter, next, StopIteration) and lazy evaluation (map, filter, zip, reversed)
  • Generators (yield, yield from, recursive generators)
  • OOP: classes, __init__, self, class vs instance attributes, methods, inheritance and super()
  • Memoization

Explicitly NOT on this exam (staff said so directly): orders of growth, linked-list mutation, tree mutation, repr strings, and special method names like __add__ / __iter__.

You still need __init__, __str__, and ordinary methods, but not __repr__ or operator methods. And since tree and linked-list mutation are out, every tree/linked-list answer builds and returns a new structure rather than changing one in place.

One naming note: this exam is scoped like past semesters' Midterm 2, so when you pull old exams for practice, use the Midterm 2 papers, not old Midterm 3s.

Cheatsheet: the foundations

The recursion skeleton

Everything is a variation of this: (1) state what the function takes and returns, (2) base case for the smallest input, (3) recurse on a smaller input, trust it, combine.

def sum_digits(n):          # positive int -> sum of its digits
    if n < 10:              # base case
        return n
    return sum_digits(n // 10) + n % 10

Tree recursion (more than one call)

"Try each choice": base cases for success and failure, one recursive call per branch, combine (add for counting, max/min for best).

def count_ways(n, m):       # ways to build n from parts up to m
    if n == 0:
        return 1            # one complete way
    if n < 0 or m == 0:
        return 0            # dead end
    return count_ways(n - m, m) + count_ways(n, m - 1)   # use m / skip m

Lists & slicing

s = [6, 5, 4, 3, 2, 1, 0]
s[0], s[-1]        # 6, 0
s[1:3]             # [5, 4]   end excluded
s[:3], s[3:]       # [6,5,4], [3,2,1,0]
s[::-1]            # reversed
s[10:]             # []   slicing never errors
s[10]              # IndexError   indexing can

Comprehensions

[x*x for x in range(4) if x % 2 == 0]   # [0, 4]
{x: x*x for x in range(3)}              # {0:0, 1:1, 2:4}

The loop variable isn't bound after the comprehension.

Aggregation

sum(s, start), max(s, key=...), min(s, key=...), len, all, any. Empty cases bite: all([]) is True, any([]) is False, sum([]) is 0. max([1,-2], key=abs) is -2 (key ranks, returns the element).

Dictionaries

d = {'a': 1, 'b': 2}
d['a']              # 1
d['z']              # KeyError
d.get('z', 0)       # 0   safe lookup
'a' in d            # checks KEYS not values
list(d)             # ['a', 'b']   the keys
list(d.values())    # [1, 2]

Lambda & higher-order functions

square = lambda x: x * x          # one-expression anonymous function
curry2 = lambda f: lambda x: lambda y: f(x, y)
curry2(add)(3)(4)                 # 7

Free variables in a lambda are looked up when it's called, not when it's defined.

Linked lists (non-mutating)

Link has .first and .rest; empty is (); no indexing, walk with .rest; test empty with not isinstance(s, Link).

s = Link(3, Link(4, Link(5)))   # (3 4 5)
s.first, s.rest.first           # 3, 4

def length(s):                  # recursive
    if not isinstance(s, Link):
        return 0
    return 1 + length(s.rest)

def range_link(a, b):           # build a NEW one
    if a >= b:
        return ()
    return Link(a, range_link(a + 1, b))

Because linked-list mutation is out of scope, every linked-list answer builds a new Link chain with the recursive result as its .rest, exactly like range_link.

Cheatsheet: the new MT3 topics

Where the exam's new weight is. Learn the Tree template, the generator template, and the class template cold.

Trees

A Tree has a label and a list of branches, each itself a Tree. A leaf has no branches.

t = Tree(1, [Tree(2), Tree(3, [Tree(4)])])
t.label               # 1
t.branches[0].label   # 2

def is_leaf(t):
    return not t.branches

Universal template: do something with t.label, recurse on each branch, combine (usually a comprehension).

def tree_sum(t):
    return t.label + sum([tree_sum(b) for b in t.branches])

def count_leaves(t):
    if is_leaf(t):
        return 1
    return sum([count_leaves(b) for b in t.branches])

def height(t):                       # edges in longest path; leaf = 0
    if is_leaf(t):
        return 0
    return 1 + max([height(b) for b in t.branches])

To build a new tree (how every transform works, since mutation is out): construct Tree(new_label, [recurse(b) for b in t.branches]).

def double(t):
    return Tree(t.label * 2, [double(b) for b in t.branches])

List mutation

These change the list in place and the mutating methods return None:

s = [1, 2, 3]
s.append(4)        # [1,2,3,4]
s.pop()            # returns 4, s is [1,2,3]
s.pop(0)           # returns 1, s is [2,3]
s.remove(2)        # removes first 2 by value
s.insert(1, 9)     # inserts, shifts right
s.extend([7,8])    # adds each element
s[0] = 99          # item assignment

+= mutates a list in place; + makes a new one. Classic diagram trap:

a = [1, 2]; b = a
a += [3]           # a and b are BOTH [1,2,3]  (same object)
a = a + [4]        # a is new [1,2,3,4]; b still [1,2,3]

is tests same object; == tests same value.

Copies are shallow. +, slicing (lst[:]), and list(lst) each make a new outer list, but any nested list inside is reused (the copy holds a pointer to the same inner list). So mutating an inner list shows up in both. += is not a copy at all, it mutates in place like extend.

Method behaviors to have cold: append adds one element and returns None (appending a list nests it); extend takes a list and adds each element, returns None; remove deletes the first matching value, returns None; pop() removes and returns the last element, pop(i) the one at index i.

Dictionary mutation

d = {'a': 1}
d['b'] = 2         # add key
d['a'] += 1        # update value
d.pop('a')         # remove, returns value

Adding keys to a dict while iterating over it raises RuntimeError.

Iterators & lazy evaluation

iter(x) makes an iterator; next(it) pulls the next value; past the end raises StopIteration.

it = iter([3, 1, 4])
next(it)           # 3
next(it)           # 1

map, filter, zip, reversed are lazy: they return iterators, not lists. Nothing is computed until you pull from them (or wrap in list/tuple/sorted). A half-consumed iterator remembers where it left off.

m = map(lambda x: x*10, [1, 2, 3])
next(m)            # 10
list(m)            # [20, 30]  (the 10 is already gone)

Generators

A function with yield is a generator: calling it returns an iterator, each yield produces one value and pauses until the next pull.

def countdown(n):
    while n > 0:
        yield n
        n -= 1
list(countdown(3))     # [3, 2, 1]

yield from <iterable> yields every value from that iterable, the key to recursive generators:

def tree_labels(t):              # every label, root first
    yield t.label
    for b in t.branches:
        yield from tree_labels(b)

yield from gen() is shorthand for for x in gen(): yield x. Use it whenever a generator relays another generator's values, especially a recursive call.

OOP: classes & inheritance

class Account:
    interest = 0.02                 # class attribute, shared by all instances
    def __init__(self, holder):     # runs on Account('Sam')
        self.holder = holder        # instance attributes
        self.balance = 0
    def deposit(self, amount):
        self.balance += amount
        return self.balance
    def withdraw(self, amount):
        if amount > self.balance:
            return 'Insufficient funds'
        self.balance -= amount
        return self.balance

class CheckingAccount(Account):     # inherits everything
    withdraw_fee = 1
    interest = 0.01                 # overrides the class attribute
    def withdraw(self, amount):     # overrides, reuses parent via super()
        return super().withdraw(amount + self.withdraw_fee)

Key rules: self is the instance; attribute lookup checks the instance first, then its class, then parent classes. super().method(args) calls the parent's version (no self passed). A class attribute is shared until an instance assigns its own, which then shadows it for that instance only.

Memoization

Cache results in a dict so each input is computed once. Turns exponential tree recursion linear.

def memo(f):
    cache = {}
    def memoized(n):
        if n not in cache:
            cache[n] = f(n)
        return cache[n]
    return memoized

Problem types & attack plans

For every coding problem, first write the one-line contract (what goes in, what comes out). Then attack by type.

Tree function

  1. Decide: computing a value (sum/count/height/bool) or building a new tree?
  2. Base case is usually the leaf: if is_leaf(t): return <answer for a lone label>.
  3. Recurse on every branch: [f(b) for b in t.branches] gives a list of sub-answers.
  4. Combine that list: sum, max, any, or wrap in Tree(new_label, [...]) to build.
  5. Often no explicit leaf base case is needed, since sum([]) over no branches handles it.

Build-a-new-tree (prune / transform / filter)

  1. Still the tree template, but you return Tree(label, kept_branches).
  2. Filtering: recurse on each branch, keep only non-None (or non-empty) results, then decide what this node returns from that list.
  3. Pass any "running total down the path" as an extra argument (e.g. n - t.label).

Generator

  1. Use yield for each value, not return a list.
  2. Base case: yield the trivial value(s), then a bare return to stop.
  3. To relay another generator's values (including a recursive call), use yield from.
  4. For "all the ways": loop over each first choice, and for each, yield from the recursive generator on the rest, gluing your choice on (yield [choice] + rest).
  5. Trace with list(gen(...)) in your head to check order.

OOP / classes

  1. __init__(self, ...) sets instance attributes; anything the object must remember goes here.
  2. Methods take self first; use self.attr to read/update state.
  3. Shared-across-all-instances values are class attributes (in the class body, not __init__).
  4. Inheritance: class B(A): gets everything; override by redefining; reuse the parent with super().method(args) (no self).
  5. For stateful problems, decide what changes per call, update that attribute, return the required value/message.

What Would Python Display

  1. Go top to bottom, tracking every variable's current value.
  2. print shows args space-separated, no quotes, and its value is None; a bare expression echoes its value (strings keep quotes).
  3. Iterators: map/filter/zip are lazy; next past the end is StopIteration; a half-consumed iterator continues where it left off.
  4. Mutation: after b = a, mutating a with append/+=/item-assignment changes b too; rebinding a = a + [...] does not.
  5. An error stops that expression; note the error type and move on.

Environment / box-and-pointer diagram

  1. One frame per call, in order, with its parent noted.
  2. Lists/dicts are objects drawn once; variables point at them; aliases share one box.
  3. On mutation, change the object in place (every arrow sees it). On rebinding, redraw the arrow.
  4. A function defined inside another captures its parent frame; that's how closures hold state.

Mutation function

  1. Change the list/dict in place with append, pop, insert, item assignment, or +=.
  2. Return None unless told otherwise.
  3. Watch loop-while-mutating: if you insert into a list you're indexing through, advance your index past what you inserted.

How staff say to approach it

Straight from the staff's exam-prep post, and it lines up with everything above. Two moves for any tree-recursion problem: first name your cases, then name the connection between them.

Name your cases

  • Use or skip — either include the current value or don't, then recurse on the rest. The subset / with-it-without-it pattern.
  • Use this or use that — pick among a few options at each step (one step or two, this coin or that), one recursive call per option.
  • Build from smaller parts — assemble the answer from several recursive calls, like fib(n) = fib(n-1) + fib(n-2).

Name the connection

  • Sum → add the cases: rec(n-1) + rec(n-2).
  • Count → a base case returns 1 (or you add 1 as you go), then sum the recursive calls.
  • Max / min → wrap the cases in max(...) or min(...).

And never forget the base case(s).

Per-topic reminders staff flagged

  • Linked lists: you will not mutate in place; you build new ones with Link and traverse. The general recursive shape is base case if not isinstance(s, Link): (check empty before touching .first/.rest), recursive case calls func(s.rest).
  • Trees: recursion almost always means a for b in t.branches: loop with a recursive call on each b. When in doubt, the base case is is_leaf(t). Map out a tiny tree by hand to check your recursion.
  • OOP: read the problem twice and the doctests twice. They're long and every sentence matters, and the doctests often reveal behavior the description doesn't state.
  • Assignment: = on a primitive (int, bool, str, float, None) rebinds the name; = on anything else (list, Link, Tree, instance) makes the name a pointer to that object, so two names can share one object.
  • Memoization: store each computed input→result in a dict; on a repeat input, return the stored value instead of recomputing. That's what collapses the duplicate fib calls.

Exam-day strategy staff emphasized: take about 5 past Midterm 2 exams (3–10 is the range successful students do), and for every miss, write down why you missed it. During the exam, if you're stuck, think for about 6 minutes, then move on and come back. Sleep and eat well; a rested brain is the cheapest point boost there is.

Your note sheets

Two 8.5×11 sheets, front and back, that you make yourself. The provided study guides already cover syntax and simple examples, so don't duplicate them. Put templates and traps on yours, the things you'd otherwise blank on under time.

High-value things to write (that the study guides don't hand you):

  • The tree build template: Tree(new_label, [recurse(b) for b in t.branches]), plus the filter version that collects non-None branches then decides.
  • The "all the ways" generator template: loop over first choice, for rest in gen(rest_args): yield [choice] + rest.
  • The with-it/without-it tree-recursion template, plus one worked count example.
  • A worked inheritance example showing super().method(...) and a class attribute being overridden.
  • The closure-with-state pattern (a function returning a function that mutates a captured list/variable), since the diagram question loves this.
  • The mutation vs rebinding rules with one tiny box-and-pointer sketch.
  • Iterator traps: lazy map/filter/zip; next past end is StopIteration; a half-used iterator resumes.
  • Aggregation edge cases: all([]) True, any([]) False, max(..., key=...) returns the element.

Skip: basic slicing, dict .get, lambda syntax, the Link definition, those are on the provided guides. Spend the space on the templates above and 2–3 problems you keep getting wrong, written out fully. Handwrite (or type and print) and actually use them while practicing this week.
